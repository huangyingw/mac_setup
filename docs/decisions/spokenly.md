# 语音输入（Spokenly）怎么装

记录日期：2026-11-13。对应 `modules/40-spokenly` 与 `snapshots/voice_input.*`。

## 1. 参考机上的听写到底是什么

调查结果与最初的设想（「装 Spokenly，再下一个它的模型」）不一样：

| 部分 | 参考机现状 |
|---|---|
| 应用 | Spokenly 官网直装版 2.34.1（Homebrew cask `spokenly` 装的就是官网版；App Store 版不能自动粘贴，不用） |
| 听写模型 | **不是** Spokenly 内置的模型。设置里选的是「本机 OpenAI 兼容接口」，指向 `http://127.0.0.1:8765` |
| 转写服务 | `mlx_audio.server`，由 launchd（`com.huangyingw.qwen3-asr`）登录即拉起，目录 `~/.local/share/qwen3-asr-server`（Python 环境 + 模型 + 日志），模型是 Qwen3-ASR |
| 设置 | `~/Library/Preferences/app.spokenly.plist`；多数项是「JSON 编码后存成 Data」 |
| 权威来源 | `voice_input` 仓库：`service/` 下是服务的启动脚本、launchd 配置、Spokenly 设置的仓库副本；`eval/requirements.txt` 是服务的依赖清单 |

所以「模型下载好、可离线听写」的含义是：**把本机转写服务连同模型装好**。服务启动时不联网（`HF_HUB_OFFLINE=1`）。

## 2. 模型按 16GB 那一档

`voice_input` 已经按机器分了档：参考机（64GB）用 `Qwen3-ASR-1.7B-bf16`，`mbp` / `mba`（16GB）用 `Qwen3-ASR-0.6B-8bit`（选型数据在 `voice_input` 的 `docs/本地模型评测.md`）。

- 目标机一律取 `mbp` 那一档：`service/model.mbp` 与 `service/spokenly-settings.mbp.json`（盖在公共设置 `spokenly-settings.json` 上面）。
- `voice_input` 自己的安装脚本按**电脑名**挑档位。对方的电脑叫什么事先不知道（演练机的电脑名也不是 `mba`），所以模块不调用那两个脚本，自己点名用 `mbp` 的文件。
- 不装 Spokenly 自带的 Whisper 模型：参考机上那份只是历史遗留的备用，不在用。

## 3. 内容怎么到目标机

`voice_input` **不能直接公开**：`eval/*.json` 是评测用的个人口述转写文本（它的 README「隐私」一节写明远程必须私有）。因此和 loadrc 一样走快照：

- `snapshots/voice_input.include` 白名单只导出模块用到的 6 个文件，推到 `huangyingw/voice_input-snapshot`，公开的是快照；
- 目标机上用 `curl` + `tar` 取快照压缩包（不依赖 git），放在 `~/.mac_setup/voice_input`；
- 模型从 HuggingFace 官方下载，Python 依赖从 PyPI 下载，Spokenly 由 Homebrew 从官网下载。

设置里没有密钥（接口在本机、不需要密钥，相关字段是空的）。

## 4. 设置怎么做到「和参考机一样」

- 写入的是 `voice_input` 导出的全部用户可见设置项（快捷键与模式、提示音、粘贴方式、听写接口等），外加 4 个「首次启动向导已完成」的标记。
- 为什么要写向导标记：`voice_input` 把它们算作各机状态、不导出；但目标机是全新安装，不写的话 Spokenly 会弹向导，向导里选的快捷键和模型会盖掉写好的设置。取值与参考机相同。
- 设备列表、统计、用户 ID 这类随机器变化的状态不写，由 Spokenly 自己生成。
- 核对办法：`settings.py check <设置文件> <设置.json>...`，逐项比较（时间戳不比）。
- **不随设置文件走的一项**：「登录时自动启动」记在系统的登录项里，脚本写不了。参考机是开着的；目标机上装完会自动打开一次，重启后要手动开（或在 Spokenly 设置里勾上）。

## 5. 记账与恢复原状

- Spokenly 运行时会写的位置（设置、听写历史与录音、缓存等）在**启动它之前**全部认领：对方原有的挪进备份，卸载时删掉我用过留下的、放回原有的。直接删，不进废纸篓——里面有我的听写录音。
- 转写服务的一切（Python、依赖、模型、缓存、日志）都收在 `~/.local/share/qwen3-asr-server` 一个目录里，包括 uv 下载的 Python 和缓存（用环境变量改了落点）。
- 卸载时清单管不到、由模块自己做的：停转写服务、退出 Spokenly、收回给它的系统授权（`tccutil reset`，只在应用是我们装的时候）、删钥匙串里它自己写的记录（只在安装时确认原来没有的时候）。Homebrew 下载缓存里的安装包由框架记账（`brewcache`）、统一清掉。
- **清单里没有本模块的记录时，清理脚本什么都不做**。恢复原状会依次跑每个模块的清理脚本；最初的版本无条件退出 Spokenly，结果别的分支用自己的状态目录跑恢复原状时，把演练机上正在跑的 Spokenly 结束掉了。
- **共用的上级目录只在空了的时候才删**。`~/.local`、`~/.local/share`、`~/Library/LaunchAgents` 原来不存在时由本模块建出来，记为 `newdir`（不是 `path`）：`path` 在恢复原状时是整个删掉的，会连带删掉别人后来放进去的东西。最初的版本记成了 `path`，2026-11-13 在演练机上因此删掉了 loadrc 分支放在这几个目录里的测试环境（已交接告知对方）。现在改用框架的 `ms_claim_dir`，由 `uninstall.sh` 最后一步统一处理（空了才删），见 `modules/README.md` 第 3 条。

## 6. 必须人工做的

麦克风和辅助功能两项系统授权没有办法用脚本授予（系统的隐私数据库受保护），安装结束时列出来。Spokenly 不需要登录。

**首次打开的确认框**（「这是从互联网下载的应用，确定要打开吗」）：

- 实测：这个确认框没人点的时候，Spokenly 的进程一直挂在启动之前（一行代码都没执行），写好的设置读不进去。
- 模块的做法：只对「我们刚经 Homebrew 装的、且系统判定为已公证」的这一份，在第一次打开之前去掉下载标记，免掉这次确认。系统不认可的、或对方原来就有的，不动，仍登记为人工事项。
- 取舍：这等于替坐在电脑前的人点了一次「打开」。应用是苹果公证过的、安装包经 Homebrew 校验过，卸载时整个删掉。不想要这个行为的话，删掉 `install.sh` 里那一段即可，届时结尾会多列一条人工事项。

## 7. 已知的边界

- **Intel 芯片的机器**：本机转写服务基于 MLX，只支持 Apple 芯片。模块在 Intel 上只装 Spokenly 本体并登记一条人工事项（在它自己的模型里选一个）。这条分支没有实测过。
- **Spokenly 版本**：cask 总是装最新版（2026-11-13 是 2.35.7，参考机是 2.34.1）。设置项的键名是从应用里读出来的、不是官方文档，大版本升级后可能要重新核对（`voice_input` 的 README 有记录）。

## 8. 实测记录（2026-11-13，演练机 `mba`，macOS 26.6.2，16GB）

用独立状态目录 `~/.mac_setup_spokenly`，按真实场景的那一条命令安装，再跑恢复原状，共走了三轮。

| 项 | 结果 |
|---|---|
| 安装耗时 | 1 分半（依赖的下载缓存还在时）到 7 分半（全新下载，约 1GB 依赖 + 模型） |
| 转写服务 | launchd 里 `state = running`，模型列表是 `Qwen3-ASR-0.6B-8bit`；安装脚本结尾用系统合成的一句英文做自检，识别结果一字不差 |
| 设置 | `settings.py check` 27 项全部一致 |
| 占用 | `~/.local/share/qwen3-asr-server` 3.8G（含 Python 环境、模型、下载缓存） |
| 恢复原状后 | 应用、服务、launchd 配置、设置、目录、钥匙串记录、Homebrew 下载缓存里的安装包、状态目录都没有了；废纸篓是空的；别的分支放在 `~/.local` 里的东西原样还在 |
| 恢复原状后唯一的残留 | 系统自己的图标缓存里有一个 Spokenly 的图标文件（`~/Library/Group Containers/group.com.apple.chronod/…`）。那是系统管理的受保护目录，不去动 |

**没能验证的**：

- **Spokenly 真正启动之后的表现**（不弹首次启动向导、设置保持不变、按快捷键能听写并贴进输入框）。原因：第一轮安装时（当时还没有第 6 节那段处理）系统弹了首次打开的确认框，演练机屏幕锁着、没人应答；这个待答的确认框之后一直挡着 Spokenly 的每一次启动，包括后两轮。需要有人到演练机前解锁、应答那个确认框之后重跑一轮才能验证。由此也**没能证实**第 6 节那段处理在全新机器上确实不再弹确认框。
- **用嘴说话的听写**：需要人在机器前授权麦克风和辅助功能后试。Spokenly 传给本机接口的音频格式是从它的程序里看出来的（wav），没有抓到真实请求；服务端没有装 ffmpeg，是基于这个判断。
- `mbp` 没连上（不在线），「按 `mbp` 的标准」依据的是 `voice_input` 仓库里 `mbp` 那一档的配置文件，没有去 `mbp` 上看现状。
- Intel 芯片的分支。
